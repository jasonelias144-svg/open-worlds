# Sketches: the creative side

This folder keeps the founder's conversations with DeepSeek, an AI, and the
code DeepSeek wrote in them. The rest of the repository is the development
side: the code open-worlds runs, built step by step through the course
([docs/COURSE.md](../docs/COURSE.md)). The two work hand in hand and are
kept apart. Where they meet is stated in one place, [INDEX.md](INDEX.md).

**What the sketches are.** A rough draft, like a creative team conveying a
vision in code instead of a page of boxes and arrows. Each step in the
conversation assumes the last one ran as expected and asks what to build
next. Nobody expects the code to run; bugs are part of a draft. In the
founder's words: "it is meant to be a starting point for you, not an end
point." The house rules ([docs/COLLABORATING.md](../docs/COLLABORATING.md))
apply when code comes into open-worlds itself, not to the draft.

**What the sketches are not: the standard.** The standard is open-worlds'
own code (`multiverse/`, `world/`, `chem/`) and its documents (`docs/`).
Nothing in open-worlds imports anything from here. A reader, DeepSeek
included, should build on the standard, and treat this folder as a record
of earlier ideas.

## What is here

| Path | What it is |
|---|---|
| `records/` | The conversation records, verbatim: the founder's messages and DeepSeek's replies |
| `deepseek/012-04-00/` | The code from record 012-04-00, written out file by file |
| `tools/extract.py` | Writes the code out of a record, and checks it against the record |
| `tools/names-012-04-00.json` | Which code blocks to take, the names of blocks that don't state one, and the files changed since |
| `tools/known_failures.py` | Rewrites a folder's `known-failures.txt` from a fresh run |
| `requirements.txt` | What the sketches' tests need (pytest, cryptography); open-worlds itself never installs it |
| `INDEX.md` | Each component: where it is in the record, its files, how its tests fare, and where it meets the course |

## Generated by AI

DeepSeek's replies in the records, and all the code in `deepseek/`
(except the files listed below as ours), were generated by DeepSeek, an
AI. They are kept as written. They have not been checked for accuracy,
apart from what the test results in each `known-failures.txt` show.

## How the code is kept

- **As written.** `tools/extract.py` takes each code block that names a
  file and writes it out byte for byte. CI runs `extract.py check`, which
  fails if any file differs from the record without being listed under
  `"changed"` in the names file. Some blocks in the record are additions to
  an earlier file ("In wcp_http_shim.py — two updates"). Those are kept as
  their own files, named `file@LINE`, LINE being the record line where the
  block's code starts.
- **With its test results.** `known-failures.txt` lists every DeepSeek test
  that fails as the code stands here, with its error. `conftest.py` makes
  each listed test an expected failure, strictly: if a listed test starts
  passing, or a listed one no longer exists, the run fails until the list
  is updated. So a green run means the list is exactly true. The results
  are for the whole folder run together, as CI runs it; a few tests behave
  differently when their file runs alone.
- **Fixed in small, listed steps.** A fix makes code do what the draft
  says it does, often by applying DeepSeek's own later addition. It doesn't
  change the design. Each changed file is listed in the names file and in
  INDEX.md, with the reason; git history shows the exact change.
- **Ours, not DeepSeek's:** `README.md`, `conftest.py`, `pytest.ini`,
  `known-failures.txt` and `sketch_status_test.py` in each code folder, and
  everything in `tools/`.

## Running it

```
python3 -m pip install -r sketches/requirements.txt
cd sketches/deepseek/012-04-00 && python3 -m pytest -q
```

The tests start small web servers on this machine (127.0.0.1) and run
some Python subprocesses. They reach nothing outside the machine.
Components 11 and 20 can load a language model of about 1 GB if
`transformers` and `torch` are installed. CI doesn't install them, and
those components' tests don't load as written.

## Rights and personal data

- Everything in this repository is public domain (CC0 1.0), as far as it
  is ours to give: the founder's messages, and DeepSeek's outputs, which
  DeepSeek's terms of use (section 4.2, updated 2026-03-27) assign to the

  AI, which this file does.

  copyright. It names them and, as commentary in a lesson, quotes at most a

  the code are in the public domain.
- The records name the founder by first name only, as the founder decided.
  Nothing more personal is to be added (AGENTS.md).

## When a record grows

The founder adds to a record over time. The new version replaces the copy
here only after a check that the old copy is an exact prefix of it, so
that nothing earlier changed. Then the code is written out again, and the
test results are rerun.
