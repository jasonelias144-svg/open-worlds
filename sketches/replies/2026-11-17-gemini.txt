3. WHAT TO DO NEXT
======================================================================

You made a room's log checkable by someone outside, attacked the
check, and repaired it. The Commons, the list of rooms, has the same
fault and one more. Two findings, both tried here:

  A. verify_commons takes a Commons, and a Commons can only be built
     by the crate's own honest code: its records are private and it
     holds the Commons' private key. So no test can hand the check a
     forged list of rooms.

  B. A record of the Commons can't be read back at all. Written to
     JSON it holds the key "type" twice:
         {"type":"room_registered","type":"room_registered",
          "commons_id":"did:key:...", ...
     and reading it fails: "duplicate field `type`". The enum
     CommonsRecord is tagged with "type", and each struct inside it
     has a field of its own that is written as "type". So the list of
     rooms can't be published and read by anyone today.

The four steps below do for the Commons what your first three did for
a room. The founder decides when to go on, and may choose otherwise.

STEP 1 (this reply). The Commons' log, read from outside.

  In src/commons.rs:

      pub struct CommonsLog {
          pub commons_id: DidKey,
          pub records: Vec<CommonsRecord>,
      }

  - It derives Clone, Debug, Serialize and Deserialize, and its fields
    are public, so a test can build one, change one, and read one
    from JSON text.
  - Commons gains  pub fn log(&self) -> CommonsLog  (never the
    keypair).
  - pub fn verify_commons_log(log: &CommonsLog) -> Result<()>  does
    everything verify_commons does today, from the log alone.
  - verify_commons(commons) becomes verify_commons_log(&commons.log()),
    so that there is one check.
  - Repair finding B: a record written to JSON holds "type" once, and
    reads back as the same record.

  What must not change: a record's hash, and the body its proofs are
  signed over. Today both are taken from the struct inside the enum,
  with its one "type" field (hash::hash_of and hash::body_for_signing
  on a RoomRegistered or a SiblingDeclared). Keep that, so that every
  proof made so far still verifies. The four earlier tests that use
  the Commons must pass unchanged: commons_registration_verifies,
  sibling_declaration_verifies, sibling_rejects_same_key and
  succession_end_to_end.

  Leave Commons.world_id as the public field it is: two demos read
  it. We close it here when your work is joined.

  Add one new test file, tests/commons_outside.rs, with three tests:
    1. a Commons with one room registered: its log, written to JSON
       text and read back, verifies;
    2. the same for a Commons with a sibling declared;
    3. a record read back from JSON has the hash it had before it was
       written.

  Expected: 69 tests pass (66 and your 3).

The test files are left out of part 5 to keep this file short. What

From your own tests/attack.rs, the two helpers that sign a forged
record of a room. A test file can't import from another, so copy what
you need:

    fn sign_single(rec: &Record, signer: &Keypair) -> ProofOrArray {
        let body = body_for_signing(rec).unwrap();
        let sig = signer.sign(&body);
        ProofOrArray::Single(Proof::create(signer, &sig))
    }

    fn sign_dual(rec: &Record, subj: &Keypair, room_kp: &Keypair)
        -> ProofOrArray {
        let body = body_for_signing(rec).unwrap();
        let s1 = subj.sign(&body);
        let s2 = room_kp.sign(&body);
        ProofOrArray::array(vec![
            Proof::create(subj, &s1),
            Proof::create(room_kp, &s2),
        ])
    }

  with, at the top of that file:
